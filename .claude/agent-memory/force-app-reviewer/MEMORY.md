# force-app-reviewer memory

Shared, checked-in notes from earlier force-app reviews. One dated line per lesson; newest last.

- 2026-10-02: seeded. `scheduledTask.test.ts` fails only if Electron's binary is missing (`npm ci --ignore-scripts`): not a regression. The sidecar `stop()` test is `skipIf(!win32)` by design.
- 2026-10-02: D1LC has five implementations (backend, filter-service, scripts/diag, process_force.m, liveCache.ts); `scripts/diag/d1lc.py` is the one most often forgotten. (filter-service now round-trips the v2 trailer as of the review-fix batch.)
- 2026-10-03: `npm ci` once, in one shell; a second/killed run corrupts node_modules (ENOTEMPTY). Env: no pytest preinstalled; venv + `pip install -e "apps/force-app/backend[dev]"` takes ~1 min. diag-service needs sklearn (a venv without it fails 20 tests: env, not code); `ruff check` in backend is clean after the batch.
- 2026-10-03: not a bug: invariant 2 (seq refs) holds in all Live* components; no `v-html`; main-window webPreferences safe; backup-server/relay having no auth is by design (tailnet-only); backup `ingest_chunk` offset handling is correct and the new idempotent `/ingest/start` is compatible with `backup.py`'s offset client. Do flag a `--host 0.0.0.0` bind of the recorder.
- 2026-10-03: recurring class: guards by string match (`is_safe_id`, backup `_session_dir`) ignore Windows drive-relative names like `C:` (fixed in batch via `:` reject + basename/commonpath). Any new id-guard should be checked against both path flavours.
- 2026-10-03: hotspot `workspace.ts` upload: now resumable (`uploadResume.ts`, in-memory per-capture progress); no unit test for `createWorkspace` start/stop; desktop `updater.ts` has tests since the batch.
- 2026-10-03: Settings > Connectivity pinned all five endpoints (incl. per-launch `recorderUrl`) in old versions; batch only stops NEW pinning and Reset returns to /config.json base; nothing migrates already-pinned overrides.
- 2026-10-03: hotspot ForceDashboard: every async writer to `detail.value` needs the `opGuard.begin(d.id)` / `live()` check (done for build/bake/render/stats). `cancelAll()` runs in the `detail.id` watcher, which is registered late: a poll started by an EARLIER-registered watcher in the same flush would be cancelled (no such path found).
- 2026-10-03: keep-alive covers only `StandaloneForceDashboard` (AppShell `include`). FrmCloud/FrmOctree now tear down on deactivate and use a keyed fresh canvas (`glLifecycle.ts`); `DiagnosticsWorkbench` per-mount document click listener leak was not rechecked. The Directus host has no keep-alive, so deactivate paths never run there.
- 2026-10-04: origin guard (`origin_guard.py`) is OK for: desktop (`RECORDER_CORS_ORIGINS=app://force`, Origin-less main-process fetch + health probe), pop-outs (same app:// origin), force-app-verify (Vite :5180 is in the default list; python/Playwright clients send no Origin). Known, documented break: Caddy `/recorder/*` needs RECORDER_ALLOWED_HOSTS + CORS origin. Not a finding.
- 2026-10-04: hotspot, pop-out windows: they learn state ONLY from relayed WS messages. `RecordClient.reconcile()` adopts done/error/idle locally without relaying, so after a missed `done` or backend restart pop-outs keep a lit "recording" dot and `state==='recording'` gating.
- 2026-10-04: pre-existing: web `stop()` calls `labamp.setMode('RESET')` right after the stop returns, but `/labamp/mode` is `_busy()`-guarded and `_busy()` includes `finalizing`, so the 409 is swallowed and the amp stays in MEASURE for any cut whose finalize outlasts `loadFinished`'s ~2.4 s retry. Same shape for any new post-stop hardware call (NI-DAQ guards extend it).
- 2026-10-04: FRM<->Signals linking (map pick/rings, ContextMenu): hotspots are window-level key listeners (ContextMenu's capture-phase Escape runs before the dashboard's bubble-phase one, so "menu open" guards see the menu already closed) and right-click-vs-drag guards: `contextmenu` fires on mousedown on macOS/Linux and on mouseup only on Windows, so a press/release slop check only works on Windows.
- 2026-10-04: octree picking rebuilds the octree path from the live cache (octreePathParams). The cache window IS the octree window (both start at the auto cutstart), so anchor on c.t[0]/c.t[N-1], not csSec/ceSec ((cs-1)/Fs only equals t if Time = (n-1)/Fs). Per-right-click buildPath is ~20 B/sample (100 MB at 5M).
- 2026-10-05: R1 hotspot — `pickReplayCut` hydrates link/meta/machining from the archived op; any "persist on leaving Replay" path stores that cut's sample/operator/machine. Debounced publishers that check state at fire time (not push time) have this class of bug.
- 2026-10-05: X1 `withHeight` mutating `pos` is safe (fresh cloud each build, GPU path off when zSeries set). Supersedes the 2026-10-04 zv-flat note.
- 2026-10-05: `SaveCutDialog.startNew()` is also the failed-state Close; check any `newRun` semantics against it.
- 2026-10-05: `replay.cacheId` is never reset, so setSource's `!replay.cacheId` guard skips the Replay-entry clear on every re-entry after a first pick; any leave-Replay restore makes the re-entered form disagree with the loaded cut. Check re-entry, not just first entry.
- 2026-10-05: SaveCutDialog's `failed` state covers start AND acquisition/finalize failures (`describeRecordingFailure().rawKept`); sequence-step decisions there must branch on rawKept. Re-review 79eda2e..HEAD: web 417, plotting 491 tests + both typechecks green.
- 2026-10-06: view-link apply in ForceDashboard: anything onCloudLoaded or op-change watchers re-seed later (crop handles, mode) must be re-applied after the async cache parse — check the ordering of async seeding, not just the first apply.

- 2026-10-06: Record nidaqChannels is the autoassigned model list on real rigs (first boot), never the default; "custom list" logic must compare against the model, not the default.

- 2026-10-06: the cutting-metrics spiral diameter model only applies to facing/parting/grooving (MT-F, MT-P, MT-G); OD, roughing, boring, threading and drilling keep a constant D. It must use the dashboard spiral's origin (`activeCrop.start`) and feed (`editFeed`) so D_mid matches the radial axis.
